What the scanner actually catches

Real findings from the shipped engine, each with a one-command automated fix. Not a feature grid: a findings ledger.

ASI05

Arbitrary shell execution exposed to the agent

Any hijacked prompt becomes a root shell on your host. Found in 'execute_bash_command'.

agentsec fix → sandboxed microVM + HITL gate
ASI01

Prompt injection with no instruction boundary

Untrusted email text reaches the reasoning loop undelimited. One override phrase away from goal hijack.

agentsec fix → injects <user_data> isolation
ASI03

Plaintext credentials hardcoded in MCP manifests

Kubernetes bearer token sits in cleartext env config, readable by every tool the agent calls.

agentsec fix → vault reference ${KUBECONFIG_TOKEN}
ASI02

Destructive database ops without confirmation

'delete_all_user_records' executes with no two-phase commit or human gate.

agentsec fix → two-phase human confirmation
ASI06

Unbounded recursive agent delegation

Sub-agents spawn sub-agents with no depth cap: cascade loops that drain compute budgets.

agentsec fix → max_depth + turn budget
ASI07

Unencrypted HTTP transport for remote MCP tools

Agent tool calls cross the network in plaintext, exposed to man-in-the-middle capture.

agentsec fix → upgrade to HTTPS

Three layers, one gap

Code linters and prompt filters both stop short of the agent execution loop. That gap is the whole product.

Code Linters (Snyk)

  • ‒ Static syntax in Python / JS files
  • ‒ Cannot read prompt instructions
  • ‒ No MCP manifest awareness
  • ‒ Blind to agent recursion

Prompt Guardrails

  • ‒ Never sees tool schemas
  • ‒ No CI/CD gate for configs
